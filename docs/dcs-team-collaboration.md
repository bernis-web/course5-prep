# DCS 团队协作文档（四人小组）

> 适用对象：课程小组的四名成员。读完这一份，你应该能回答三个问题：
> 我们要不要进同一个项目？角色怎么分？钱（计费组 / 体验金）怎么算？

## 一、先分清三件不同的事

| 概念 | 管的是什么 | 在哪里管 |
| --- | --- | --- |
| 项目成员 | 谁能看到、操作这个项目的数据、工作流和结果 | DCS 项目的成员设置 |
| 计费组成员 | 项目的花费从哪个计费组扣、谁在组里 | DCS 计费 / 计费组设置 |
| GitHub 协作 | 清单、参数、脚本、脱敏结果的版本同步 | GitHub 仓库 |

三件事互相独立：进了同一个项目不等于进了同一个计费组；GitHub 只同步文件，不碰 DCS 里的数据和权限。

## 二、项目成员：官方规则摘要

依据当前官方《项目》帮助文档：<https://www.dcs.cloud/helpcenter/zh/usermanual/project.html>

- 项目所有者唯一。
- 邀请方式两种：项目概览的成员区，或「项目设置 > 成员 > 添加成员」，用用户名或邮箱邀请。
- 角色共三种：
  - **管理员**：协助管理项目。
  - **分析员**：可以管理项目数据并运行工作流 / 工具 / 分析。
  - **访客**：只读。
- 需要跑分析的组员**不要设为访客**，访客跑不了任何分析。

## 三、计费组、体验金与运行控制

依据当前官方《名词解释》和《计费功能》帮助文档：

- <https://www.dcs.cloud/helpcenter/zh/pricing/definitions.html>
- <https://www.dcs.cloud/helpcenter/zh/pricing/billing-function.html>

- 一个项目只能关联**一个**计费组；一个计费组可以关联多个项目。
- 默认项目关联默认计费组。
- 官方当前明确写明：**免费体验金不能转移**。因此四个个人账号的体验金不能因为加入同一项目而自动合并。

当前官方项目页说明所有者和管理员可以调整项目及成员预算，但公开帮助页没有承诺“达到预算即自动停止实例”。因此本仓库采用保守运行规则：预算设置只作为控制和提醒证据，任何真实运行仍须由指名负责人监控并手动停机。

## 四、推荐的角色结构：分两种场景

课程共享项目可能由老师或课程方拥有，不能默认学生能当（或转正为）所有者。按项目归属分两种场景：

### 场景一：老师 / 课程方拥有共享项目（默认按此处理）

| 成员 | 角色 | 职责 |
| --- | --- | --- |
| 老师 / 课程方 | 所有者 | 项目唯一所有者，管理成员、数据和授权 |
| 组员 A | 管理员（仅在老师授予时） | 老师不在时协助管理成员和设置；未被授予就没有此角色 |
| 其余组员 | 分析员 | 管理数据、运行工作流 / 工具 / 分析 |

没有被授予管理员也完全够用：分析员就能跑分析；需要管理操作（加成员、改设置）时找老师。

### 场景二：学生自建共享项目

只有确认课程方不提供共享项目、由学生自己新建时，才由一名学生担任所有者：

| 成员 | 角色 | 职责 |
| --- | --- | --- |
| 成员 A | 所有者 | 项目唯一所有者，管理成员、最终把关 |
| 成员 B | 管理员（备用） | 所有者不在时兜底管理 |
| 成员 C、D | 分析员 | 管理数据、运行工作流 / 工具 / 分析 |

原则（两种场景相同）：需要跑分析的人一律设分析员或更高，不设访客。

### 共享项目的预算与停机责任

- 共享项目可以由所有者或管理员调整项目和成员预算（见第三节）。
- 不把预算设置视为自动停机保证，不能指望平台兜底。
- 因此每次真实运行前必须**指名一名当次停机负责人**，达到时长 / 内存 / 费用上限或任务结束时，由该负责人手动停止实例；组长应把负责人名字记进当次运行记录。

## 五、体验金：进同一个项目不会合并

- 加入同一个项目，便于共享数据、结果和权限。
- 但它**不会**把四个账号各约 100 元的体验金合并成一笔。
- 官方当前明确限制的是**免费体验金不能转移**；不要把付费余额的其他规则与体验金混为一谈。

## 六、现阶段（学校付费 / 课程计费组明确前）怎么干

- **共享项目**：用于协调、查看数据，不作为计算主力。
- **计算**：四个人各自在自己的项目和计费组里安排，用掉各自的体验金。
- **GitHub**：同步清单、参数、脚本和脱敏结果。
- **复制大数据之前**，必须先确认三件事，缺一不可：
  1. 权限（有没有权利复制这份数据）；
  2. 存储 / 复制成本；
  3. 数据一致性（复制后和原件是否一致）。

  未确认前不能擅自复制。

## 七、怎么邀请（6 步）

场景一中由老师 / 课程方所有者或其授权的项目管理员添加成员；场景二由学生所有者或项目管理员操作。步骤相同：

1. 有成员管理权限的所有者或项目管理员登录 DCS，打开共享项目。
2. 进入「项目设置 > 成员 > 添加成员」（或项目概览的成员区）。
3. 输入被邀请人的用户名或邮箱。
4. 按第四节的分工表选择角色（管理员 / 分析员）。
5. 点击添加；若页面或邮件明确提示还需被添加者确认，再线下通知对方处理，不预设一定存在“待接受”步骤。
6. 操作者在成员列表确认对方已出现、角色和数据授权范围正确。

## 八、邀请后的核对清单

被邀请人加入后逐项确认：

- [ ] 区域一致（与项目 / 数据所在区域相同）；
- [ ] 项目可见（登录后能看到共享项目）；
- [ ] 角色正确（需要跑分析的人不是访客）；
- [ ] 数据可见（能看到项目里的数据和结果）；
- [ ] 计费组 / 预算归属已确认（清楚项目关联哪个计费组、预算怎么设）；
- [ ] 运行人知道谁负责停止实例（不把预算设置当作自动停机保证，必须人工监控并停机）。

## 九、结论：要不要拉进同一个组

- **要**：共享课程数据时，需要加入**同一个项目**。
- **不要**：不要为了“合并体验金”而误解项目或计费组关系——免费体验金不会因加入同一项目而合并，也不能转移。

一句话：同项目共享数据，各自计费用各自的体验金，GitHub 同步产物。
