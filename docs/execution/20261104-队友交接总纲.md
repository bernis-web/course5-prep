## 0 三分钟看懂

**项目在做什么**：拿三个物种（人 / 小鼠 / 斑马鱼）的心脏单细胞数据，比较四种「跨物种细胞类型迁移」方法的实际表现，产出一张**场景 → 该用谁**的选型表，并把这些结论做到可复现。

**四种方法**：

| 方法 | 一句话原理 | 代价 |
|---|---|---|
| ortholog-PCA（我们叫 oPCA） | 把两物种压到同一批 1:1 同源基因上，做 PCA，再按最近邻投票 | 27 秒，纯 CPU，峰值 1.3 GB |
| SATURN | 用 ESM2 把基因翻成蛋白质语言嵌入，压成「宏基因」后对齐 | 要 GPU 训练 |
| SAMap | 建两物种基因的同源关系图，按图找细胞对应 | 依赖最多，最不稳定 |
| scVI | 生成模型，把多物种细胞一起训练到 10 维潜空间 | 要训练，CPU 8.5 分钟（平台 2c8g 实测 15m16s） |

**四条结论**：

1. **没有全面赢家。** 所以本项目**不排总分冠军**，只做「场景 → 推荐谁」。
2. **近缘场景（人↔鼠）简单方法就够**：oPCA 与 scVI 基本打平（两向均值 0.6582 vs 0.6289），而 oPCA 只要 27 秒、不用 GPU。
3. **跨门场景这一族方法都做不了**：七鳃鳗↔小鼠双向准确率 4.6–5.8%，比随机猜（约 7.7%）还低，也远低于多数类基线（21.7% / 30.6%）。这是有价值的**负结果**。
4. **批次混得好不好，不能当方法优劣的依据**：三个方法都没把物种混匀（iLISI 1.006–1.120，满值 3），但它们的迁移能力差很多。

**三个必须随结论一起说的限定语**（单独说结论就是断章取义）：
- 全部结果都是 **transductive / in-sample**（同批数据重评估），不是 held-out、不是 inductive；
- 规模只有 **4,606 个细胞**（跨门是 55,694 个，另一套数据）；
- macro-F1 用 **union 口径**，且必须并列报 **分母 n_q**。

## 3 结果一：门内四方法对比（coarse macro-F1，union 口径）

**这是唯一的权威数字表**，全部从 18 份逐细胞预测文件独立重算。

| 方向 | ortholog-PCA | SATURN v99 | SAMap | scVI |
|---|---|---|---|---|
| 人→鼠 | 0.6435 | 0.4147 | 0.1127 | **0.6683** |
| 鼠→人 | **0.6729** | 0.4010 | 0.0401 | 0.5895 |
| 人→斑马鱼 | 0.1654 | 0.2479 | 0.0477 | **0.4014** |
| 斑马鱼→人 | 0.1512 | 0.4021 | n/a | **0.4290** |
| 鼠→斑马鱼 | 0.2177 | 0.6500 † | n/a | 0.4248 |
| 斑马鱼→鼠 | 0.4405 | 0.6510 † | n/a | 0.4786 |

- 「n/a」= 该方向上没有任何细胞通过映射，无法评估。
- **† 2026-10-30 修订（重要）**：SATURN 这两格的分数受**口径偏差**影响——它输出的是原始细胞类型，映射不到 coarse 的预测被**丢弃，细胞同时退出分母**，等于按预测结果筛样本，分数被抬高 0.04–0.19。公平口径（保留细胞、不可映射算错）下为 **鼠→斑马鱼 0.4560、斑马鱼→鼠 0.4588**，此时两个方向都是 **scVI 显著更好**（同细胞配对检验 Δ=−0.1713 / −0.0709，95% CI 均不含 0）。
- **为什么鼠↔鱼两行故意不加粗**：这两格胜负取决于口径，加粗就等于替读者选了口径。

**为什么不能靠这张表定冠军**：四个方法的分母 n_q 不同（oPCA 1499–1528、scVI 1499–1528、SATURN 459–1309、SAMap 307–1368），而且 SATURN 的 n_q 本身就是"预测恰好可映射"筛出来的。**跨方法比大小 ≠ 公平比较**，真正的比较必须落在同一批细胞上（`results/bootstrap-20261030/pairwise.json`，13 组配对检验）。

### 3.1 为什么用 macro-F1 不用 accuracy

accuracy 会被多数类绑架。人→鼠的多数类基线 accuracy 有 **48.17%**，但它的 macro-F1 只有 **0.0813**——因为它只对一个类好。课程要求 macro-F1 就是为了惩罚少数类全错。

### 3.2 一个 accuracy 是怎么算出来的（人→鼠，完整拆解）

| 环节 | 取值 |
|---|---|
| 输入 | 人 1,528（参考）/ 鼠 1,535（待预测） |
| 同源基因 | 15,869 对 |
| 表示层 | 3,063 × 50 维 |
| 评分 | k=15，cosine，倒距离加权投票 |
| 排除 | 剔 30 个（鼠侧 status ≠ active） |
| **分母** | **1,505** |
| **分子** | **1,297** |
| **accuracy** | **1,297 ÷ 1,505 = 86.18%** |

逐类：内皮 720/725（99.31%）、免疫 197/202（97.52%）、成纤维 255/360（70.83%）、心肌 19/47（40.43%）。错误集中在「成纤维→平滑肌」82 个、「心肌→内皮」27 个。

**关键**：分母是"有资格参加评估的细胞"，排除规则一改分母就变，同一个 1,297 会算出不同百分比。**所以报分必须带 n_q。**

### 3.3 两个 macro-F1 口径

| 口径 | 算法 | 用途 |
|---|---|---|
| truth-only | 只按真实标签集取平均，多预测的类被忽略 | 平台 scVI 脚本默认 |
| **union** | 真实 ∪ 预测一起平均，多预测的类记 F1=0 | **本项目统一用这个** |

人→斑马鱼 coarse 为例：truth-only 0.4516 vs union 0.4014，**差 0.05**，足以改变"是否高于基线"的判断。

### 3.4 每个分数必须并列报的四个量

accuracy / **n_q（进入分母的细胞数与占比）** / **majority（最大真值类占比，无信息基线）** / shuffle_p（200 次置换检验，只回答"是否优于随机"，**不回答"是否优于多数类"**）。

四方法分母覆盖率：**oPCA 100%、scVI 98–100%、SATURN 29–87%、SAMap 0–91%**。

## 4 结果二：批次混合（三方法）

定义统一在 `scripts/compute_batch_metrics.py`：silhouette 用 cosine 距离；iLISI 是 k=30 邻域的物种逆 Simpson 指数；kBET 是 k=30 邻域 vs 全局物种构成的卡方检验接受率（α=0.05）。

| 指标 | ortholog-PCA（50 维） | scVI（10 维） | SAMap（150 维） |
|---|---|---|---|
| silhouette（越高越保类型） | 0.0937 | **0.1810** | 0.0431 |
| iLISI（满值 3，越高越混匀） | 1.0124 | **1.1202** | 1.0061 |
| kBET 接受率（越高越混匀） | 0.0004 | **0.0039** | 0.0011 |

三条读法：
1. 三个方法**都没把物种混匀**（iLISI 1.006–1.120，kBET 0.04%–0.39%），这是共性。
2. SAMap 两项都最差，与它 macro-F1 近乎无信号一致。
3. scVI 三项相对最好，但绝对水平仍低——只能说"相对最好"，不能据此把 scVI 当批次校正工具推荐。

**低 iLISI ≠ 方法失败**：同一份 scVI 潜空间上人→鼠 macro-F1 有 0.6683。解释是潜空间把「细胞类型」和「物种」编码在近似正交方向上。**两组证据必须一起报，只引一个就是误导。**

**SATURN 为什么没有**：产物已清理、ESM2 嵌入不存在，重训会产出不同表示造成**假对照**。这是"不可补"，不是"没做"。

## 5 结果三：跨门场景（七鳃鳗 ↔ 小鼠）

| 方向 | oPCA acc / mf1 | scVI acc / mf1 | 多数类基线 |
|---|---|---|---|
| 七鳃鳗→小鼠 | 0.0575 ± 0.0020 / 0.0235 | 0.0582 ± 0.0020 / 0.0241 | 0.2168（基线 mf1 0.0274） |
| 小鼠→七鳃鳗 | 0.0516 ± 0.0011 / 0.0257 | 0.0457 ± 0.0011 / 0.0267 | 0.3059（基线 mf1 0.0360） |

> **2026-10-30 修订**：macro-F1 由旧存值 0.0652–0.0802 改为**可从混淆矩阵复现**的 0.0235–0.0267（accuracy 与混淆矩阵完全一致，但旧 macro-F1 差约 3 倍、来源不明）。换口径后负结果更强：**两个方法的 macro-F1 都低于多数类基线**。

两个必须说明的取舍：小鼠有 6 类细胞七鳃鳗没有（占小鼠细胞 62.2%），全部排除出评估；七鳃鳗侧只有 56.7% 的基因非零。

## 9 三条纪律（改任何东西之前先读）

1. **不把 transductive 写成 held-out 或 inductive。** 现有全部结果都是同批数据重评估，写成留出评估就是造假。
2. **不按总分排冠军。** 只做「场景 → 方法」，不做「方法 → 分数排名」。
3. **限定语随数字一起出现。** 任何 macro-F1 引用必须带「union 口径 + 分母 n_q + transductive」三件事。

另外两条工程纪律：
- **不覆盖旧文件**：新结果写新目录/新版本（选型指南已到 v6，别改 v5）；
- **数字从文件读，不凭记忆写**：所有表格用脚本从 `metrics.json` 生成，或逐格核对过。

## 10 常见疑问

**Q：为什么不排一个总分冠军？**
A：四个方法的分母、特征空间、训练方式、统计强度都不同，比大小不公平。用同一批细胞做配对检验才能比，而结论仍然是"场景不同、推荐不同"。

**Q：为什么跨门结果这么差，是不是跑错了？**
A：没跑错。随机猜约 7.7%，我们实测 4.6–5.8%，连随机都不到；macro-F1 也低于多数类基线。这是**实测出来的负结果**，价值在于证明"这一族方法在当前数据与注释体系下做不了跨门"，不是失败。

**Q：为什么 SATURN 的鼠↔鱼两格要打 †？**
A：它把不可映射的预测直接丢掉，那些细胞同时退出分母，等于按预测结果筛样本，分数被抬高 0.04–0.19。公平口径下翻转成 scVI 更好。

**Q：为什么 macro-F1 和 accuracy 差这么多？**
A：accuracy 只看答对比例，被多数类主导；macro-F1 让每个类等权。人→鼠 accuracy 86.18% 但多数类基线 macro-F1 只有 0.0813，说明单看 accuracy 会严重高估。

**Q：我拿到预测文件想自己重算，从哪开始？**
A：`results/*/predictions/` 下的逐细胞预测 + `scripts/` 里的评估脚本；`results/bootstrap-20261030/bootstrap.json` 是已经对齐好的冻结值（0 mismatch），可以先拿它当基准。

## 12 如果只记三句话

1. **我们的百分比不是抄的**，是 8 道工序算出来的（原始数据 → 归一化 → 同源基因 → 降维 → 找邻居 → 投票 → 算分 → 存档）；换任何一道工序的定义，数字就会变。
2. **没有全面赢家**，所以不排总分，只做「场景 → 方法」的选型表。
3. **所有结论都限定在 transductive / in-sample、4,606 个细胞**；oPCA 的 seed 波动已实测 ≤0.6 个百分点，其余方法的 seed 波动未测。
