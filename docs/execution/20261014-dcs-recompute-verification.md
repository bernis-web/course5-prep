## 四、差异根因（已定位到源码行）

### 4.1 直接原因：共享基因数不同

| 方向 | 冻结 shared_genes | 回收 shared_genes | 差 |
|---|---|---|---|
| human→mouse / mouse→human | 15,869 | 15,869 | **0** ✅ |
| human→zebrafish / zebrafish→human | 9,131 | 9,311 | **+180** |
| mouse→zebrafish / zebrafish→mouse | 7,670 | 8,160 | **+490** |

### 4.2 根本原因：`one_to_one()` 映射的键方向在两边不一致

两个脚本各自构造 `fh`（人-鱼）与 `fmm`（鼠-鱼）映射，**键的方向相反**：

| 脚本 | `fh` 的键 | `fh` 的值 | 在 MAPS 中的用法 |
|---|---|---|---|
| **权威** `ortholog_pca_local_v1.py` | **鱼基因**（`ppardb`） | 人基因（`PPARD`） | `("human","zebrafish"): fh` ← **键方向与用途不符** |
| **平台** `ortholog_pca_dcs_v2.py` | **人基因**（`PPARD`） | 鱼基因（`ppardb`） | `("human","zebrafish"): fh` ← 键方向与用途一致 |

**实测验证**（用权威脚本自身逻辑，当前输入）：

```
权威脚本自身逻辑: h->z 9131, m->z 7670   ← 与冻结值完全一致 ✅
平台脚本逻辑    : h->z 9311, m->z 8160   ← 与回收值完全一致 ✅
```

→ **结论**：回收产物的差异**不是随机误差、不是环境差异、不是数据变化**，而是**平台脚本修正了权威脚本的一处键方向错配**，导致参与 PCA 的基因集合不同（多 180 / 490 个基因），进而改变投影与 KNN 结果。

### 4.3 已排除的因素

| 假设 | 排除依据 |
|---|---|
| 输入数据不同 | 三份 h5ad SHA-256 **与冻结 manifest 逐字节相同**（`af41618b`/`7fda583d`/`6b1e8798`）；ortholog 三件、映射表亦相同 |
| 细胞数不同 | 1528 / 1535 / 1543，与冻结一致 |
| 基因名重复去重 | 实测斑马鱼有 142 个重复名，但去重与不去重得到**相同**的 shared 数 |
| 运行环境（sklearn/numpy） | 人-鼠方向在完全相同的环境下**逐格一致**，环境差异无法解释"仅鱼方向差异" |
| 协议参数 | seed=0 / K=15 / nperm=200 / npcs=50 / min_shared 均一致（平台 100，权威 1000，但两方向实际 shared 均远超阈值，不触发） |

### 4.4 产物结构差异（非数字差异）

| 项 | 冻结件 | 回收产物 |
|---|---|---|
| predictions | 18 个文件（方向×层级，如 `coarse_human_to_mouse.json`） | **6 个文件**（每方向一个，内含 exact/coarse/fine 三层数组） |
| confusion | 18 个文件 | **6 个文件**（同上嵌套结构） |

→ 结构不同导致逐字节 SHA 对照**无法进行**（0/36），但这属**打包形式差异**，不影响数字可比性（数字已按方向×层级逐格比对）。
