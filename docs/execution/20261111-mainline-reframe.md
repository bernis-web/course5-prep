## 二、准确率低的真因排序（Claude 诊断 + 我核实）

要区分两个不同的问题：**「绝对分数为什么低」**和**「方法排名可不可信」**，排序不同。

| 排序 | 因素 | 影响绝对分数 | 影响排名 | 一句话 |
|---|---|---|---|---|
| 1 | **复现协议正确性** | **最高** | 高 | 我们跑的不是原文方法，是大幅缩水的重实现 |
| 2 | **同源覆盖** | 高（仅 SAMap/oPCA） | 高 | SAMap 的 1:1 图不是 SAMap 的全图 |
| 3 | **数据规模** | 中 | 中 | 差 20–40 倍，非 2–3 个数量级 |
| 4 | **评测协议** | 中 | **最高** | 混指标 / 混映射 / 丢样本 / transductive |
| 5 | **训练算力** | **最低** | 低 | CPU 上 loss 已收敛到 0.07–0.08；GPU 是放大规模的前提，不是低分的原因 |

### 2.1 最扎心的一张表：我们跑的 SATURN 不是官方配置

| 项 | 我们实际 | 官方默认 / 原文 |
|---|---|---|
| HVG 候选 | 每物种 2,500 → 内部 **2,000** | **8,000** |
| macrogenes | **1,000** | **2,000** |
| pretrain epochs | 约 **50** | **200** |
| 设备 | **CPU 1c4g** | GPU |
| 评估器 | **KNN15** | 官方用 **logistic regression** |
| 细胞数 | 1,500/物种 | 几千到几万/物种 |

出处：`wheelhouse/saturn-src/train-saturn.py:1014-1018`（官方默认）、
`docs/saturn-smoke-evidence-20260922.md:49`（我们的配置）、`train-saturn.py:844`（官方评估器）。

### 2.2 一个概念错误要纠正

**SATURN 不使用同源图**——它的核心是 ESM2 蛋白嵌入 + macrogene 聚合 + 对抗/度量学习。
同源图是 **SAMap** 的核心。我先前把两者都归为「依赖完整同源图」，这个理解是错的。

- SAMap：我们用 MGI/ZFIN **1:1** 建图，不是原文的 **BLAST 全图**（含一对多/多对多）；
- oPCA：1:1 是设计选择，人鼠 15,869 对够用，但鱼方向会丢掉硬骨鱼全基因组复制的旁系同源；
- SATURN：不适用，对应实验是 **HVG / gene universe**（2,000 vs 8,000 vs 全 ESM2 匹配基因）。

### 2.3 两个「不能声称」的硬约束

- **配对检验必须重跑**：`results/bootstrap-20261030/pairwise.json` 里的 SATURN 值还是旧的
  （0.2479 / 0.4021 / 0.6491 / 0.6508），不是修正后的 0.1282 / 0.1386 / 0.4076 / 0.2961。
  **在重跑前，任何「scVI 显著更好」的句子都不能写。**
- **跨门负结果先别当生物学结论**：混淆矩阵显示多个七鳃鳗类被系统性预测成 `Granule_like`，
  且 13 类交集排掉了小鼠 **62.2%** 细胞、基因轴非零率只有 56.7%——
  这更像**管线/标签错位**，不是「方法在跨门尺度上失败」。

## 四、论文可行性（诚实评估）

### 4.1 现状够不够发：**不够**

| 缺口 | 为什么致命 |
|---|---|
| 没有正对照 | 审稿人第一问就是「你怎么证明实现正确」 |
| 指标不一致 | 表格自相矛盾，结论不可信 |
| 数据规模 4,606（全量 140k 可用） | 小于原文 1–2 个数量级 |
| 全部 transductive | 不能声称泛化 |
| 3 个方法单 seed；bootstrap 按细胞、忽略供体 | CI 过窄，p 值不可靠 |
| 标签空间 9 类含物种特有类；跨门排掉 62.2% 小鼠细胞 | 分数被标签空间结构污染 |
| SATURN 训练命令缺失；SAMap 冻结数字来自与 checked-in 不同的 WDL 脚本 | 「可复现」声明站不住 |

### 4.2 三个候选去处

| 去处 | IF 量级 | 适合 | 需要补 |
|---|---|---|---|
| **Briefings in Bioinformatics** | ~6–8 | 综合 benchmark + 评测审计 + 实用指南 | 多数据集、多物种对、全量、held-out donor、正对照、开放代码（3–6 个月） |
| **Bioinformatics**（Application Note） | ~4–5 | 一个可复用工具或一套严谨协议 | 比 BIB 快 |
| **GigaScience** | ~7 | 数据/资源/可复现性 | 开放数据 + 容器 + 完整 benchmark |
| 现实路径：**PLOS ONE / Scientific Reports / BMC Bioinformatics** | ~3–4 | 负结果 / 方法学 note | 正对照 + 机制 + 多数据集；审稿较宽容 |

**不要投 Nature Methods / Genome Biology 的方法论文**——当前证据量级不够。

### 4.3 最值钱的资产是什么

不是那 4,606 个细胞，也不是那四个方法，而是**「分母 / 映射口径会改变结论」这件事**。
但它现在被三层壳包着：一个已被推翻的版本、一张混指标的表、一个没有正对照的负结果。
**先把这三层壳剥掉，再谈论文。**
