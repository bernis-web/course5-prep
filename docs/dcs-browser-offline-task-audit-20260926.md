## 与支持回复的关系

用户补充的客服邮件截图（工单 `TK20260921002545502`）给出了更明确的边界：外网登录时，个性分析和镜像管理模块需要华大 VPN；当前白屏属于公司网络安全策略导致的预期现象，外网访问需等待安全审批。该回复只证明 notebook/镜像管理入口的网络限制，不等于离线任务接口也必须走 VPN。

本次浏览器观察到离线任务列表和历史任务详情可读，且项目页面本身能正常打开；结合既有离线通道记录，离线任务仍可作为候选的公网流程。但在没有逐项记录接口请求和返回证据前，不能把客服回复解读为“所有 DCS API 都已确认公网可用”。

因此后续可以把“离线任务公网提交”作为候选执行路径，但在正式运行前仍需取得并固定：

1. 离线任务提交接口或页面的实际入口；
2. 任务创建所需镜像、算力和输入文件的字段；
3. 任务 ID、原始命令、日志、输入/输出路径与 SHA-256；
4. v71 训练与 v72 评估的 barcode 角色、表示层和留出关系。

## 对当前审计结论的影响

本次证据解除了一部分“找不到历史任务”的阻塞：v71/v72 批次、子任务、状态、时间、资源、镜像和运行日志均已定位。它仍不能解除 `config/eval-manifest-v73.json` 的 provenance blockers，也不能把 v72 升级为 held-out benchmark。现阶段仍只能称为 transductive/in-sample 探索性评估，除非补齐 query/reference barcode、原始命令、输入输出 hash、表示层提取方式和运行时 provenance。
