# 第 1 章 我们到底在解决什么问题

> **这章讲什么**：这个项目到底在干什么，为什么"跨物种比较"不是一件显然的事。
> **为什么重要**：后面所有方法、所有分数，都只在这个问题框架里才有意义。跳过这章，第 2 章那三个缩写对你就是天书。

## 1.1 先讲个厨房里的故事

假设有三个厨师，各写了一份菜谱：

- 中国厨师（对应 **人**）
- 日本厨师（对应 **小鼠**）
- 一个来自很远地方的厨师（对应 **斑马鱼**）

三份菜谱用的是三种语言，连"盐"这个字都长得不一样。

你想知道的**不是**"谁的菜谱写得漂亮"，而是：**他们做的到底是不是同一道菜？**

但你不能直接把菜谱摊开对，因为有三个坑：

1. **文字不通**——"盐" / "塩" / "salt" 得先对上号；
2. **有的菜名根本没有对应**——中国菜谱里的"高汤"，日本菜谱里没有单独这一条；
3. **份量标准不同**——一份写"少许"，另一份写"3.5 克"。

所以正确做法是：**先把三份菜谱翻译成同一份标准菜谱**（统一语言、统一单位、统一分类），**再比谁做出来的东西更像**。

这就是"跨物种单细胞比较"：

| 厨房里的东西 | 项目里的东西 |
|---|---|
| 菜谱 | 基因表达（每个细胞里哪些基因开着、开多大） |
| 翻译成标准菜谱 | 把不同物种的基因映射到同一套"同源基因轴"上 |
| 比谁做得好吃 | A 物种已知类型的细胞，能不能正确给 B 物种的细胞打上类型标签 |

**术语版一句话**：跨物种单细胞整合（cross-species single-cell integration）= 把多个物种的单细胞转录组数据映射到共同的表示空间，使同一细胞类型在不同物种之间可比。

> 顺带解释两个词：
> **单细胞转录组**（single-cell RNA-seq）= 把一块组织拆成一个个单独的细胞，分别测出每个细胞里所有基因的活跃程度，结果是一张"细胞 × 基因"的大表格。
> **降维**（dimensionality reduction）= 这张表有几万列（基因），人眼看不了、算距离也算不准，先用数学方法把它压成几十列，同时尽量不丢信息。

## 1.2 "细胞类型注释"是什么，为什么非有不可

一次单细胞实验的产出，就是一张表：每行一个细胞，每列一个基因，格子里是"这个基因在这个细胞里被测到多少次"。

问题来了：**这张表里没有任何一列叫"细胞类型"。**

仪器只告诉你"这里有一个细胞，它有这些基因在活动"，它不告诉你这是心肌细胞、成纤维细胞还是免疫细胞。

**细胞类型注释**（cell type annotation，就是给每个细胞贴上一个类型标签）= 根据这个细胞表达了哪些基因、最像哪一类已知细胞，判定它属于哪一类。

**为什么必须做**：

- 没有标签，你只能做无监督聚类（把相似的细胞自动堆成堆），但堆出来的每一堆**叫什么你不知道**，也就无法判断对错；
- 有了标签，才谈得上"对不对"——才能算准确率、macro-F1 这些指标；
- 跨物种比较的核心任务，本质就是 **标签迁移**（label transfer）：A 物种的标签是已知的，拿它去猜 B 物种每个细胞的标签，再和 B 的真实标签比。

一句话：**注释既是任务的前提，也是评分的标准答案。**

> **macro-F1**（一种打分方式，中文叫"宏平均 F1"）= 先对每个细胞类型单独算一次"查得准 + 查得全"的综合分，再对所有类型**等权平均**。它和 accuracy（总体正确率）的区别是：accuracy 会被"数量最多的那一类"绑架，macro-F1 会让少数类也被惩罚到。本项目主指标用 macro-F1，原因见后文。

我们的数据带三层标签：

| 层级 | 含义 | 用途 |
|---|---|---|
| exact | 原始注释，最细的叫法 | 溯源、对照原文 |
| fine | 细类 | 精细评估 |
| coarse | 粗分，**9–10 类** | 跨物种比较主要用这一层（越粗的类别，跨物种越可能真的对应） |

## 1.3 跨物种比同物种，到底难在哪

同物种比较时，基因是同一套、细胞类型的名字是同一套、样本量差不多——三样都顺。

一到跨物种，三样全崩。下面三个难点，是本项目一切设计的根源。

### 难点一：同源基因对不上，一对一的只有一部分

**同源基因**（ortholog，不同物种里由同一个祖先基因传下来、功能大致对应的基因）是跨物种比较唯一的桥。

但这座桥很窄——我们在整个基因池里，只能挑出**一对一（1:1）直系同源**的那些：

| 物种对 | 1:1 同源对数 |
|---|---|
| 人 ↔ 小鼠 | 15,869 |
| 人 ↔ 斑马鱼 | 9,311 |
| 小鼠 ↔ 斑马鱼 | 8,160 |

对比一下基因总数（每物种 27,519–32,732 个），就能看出**大量基因在对面没有对应项**，映射时只能被丢掉。

丢得越多，信息损失越大；而斑马鱼与人的进化距离最远，丢得最狠——这直接解释了后面"人 ↔ 斑马鱼方向分数最低"。

### 难点二：细胞类型的名字不统一

同一类细胞，三份数据里可能写成三个名字。更麻烦的是**有些类型只存在于一个物种**。

真实例子（跨门脑数据）：小鼠有 6 类细胞（EX / IN / SNCG / Purkinje / Golgi / Bergmann）在七鳃鳗里完全没有，这些细胞占小鼠总量的 **62.2%**，只能整批排除出评估。

所以每个项目都必须先手工做一张**标签映射表**（把各物种自己的叫法统一到一套标准名）。

我们的是 `config/heart-celltype-map-v1.tsv`：38 行、35 个 active、3 个 unmapped。

**这张表不是配菜**——它决定哪些细胞有资格参加评估，换一种映射，分母就变，分数就会变。

### 难点三：规模差几百倍

| 数据集 | 细胞数 | 相对门内 |
|---|---|---|
| 本项目门内（三物种心脏） | 4,606 | 1× |
| 跨门（七鳃鳗 + 小鼠脑） | 55,694 | 约 12× |
| HEART 原文（16 物种） | 47.9 万 | 约 100× 以上 |

规模一变，**方法的可用性就变**：我们的 scVI 在 2 核 CPU 上 8.5 分钟跑完；到 10 万细胞级别就必须上 GPU。

所以我们的所有结论**只在这个规模上成立**，这句话必须随每一个数字一起出现。

## 1.4 三个物种的家底

| 物种 | 细胞数 | 基因数 | 与人的 1:1 同源对 | 与小鼠的 1:1 同源对 |
|---|---|---|---|---|
| 人 human | 1,528 | 32,732 | —（自身） | 15,869 |
| 小鼠 mouse | 1,535 | 32,379 | 15,869 | —（自身） |
| 斑马鱼 zebrafish | 1,543 | 27,661 | 9,311 | 8,160 |
| **合计** | **4,606** | — | — | — |

补充口径：

- 数据文件：`local_human_s.h5ad` / `local_mouse_s.h5ad` / `local_zebrafish_s.h5ad`；
- 标签三层：exact / fine / coarse（coarse 为 9–10 类）；
- 跨门对照数据：LBSPA 8 物种脑数据子集的七鳃鳗 41,678 + 小鼠 14,016 细胞，共同基因轴 6,222；
- scVI 用的是三物种联合训练的**共同人类基因轴 9,018 基因**——和 oPCA 的"每方向独立成对基因集"不是同一条轴，这会影响跨方法比较。

> ⚠️ **待确认（同源对数有两版）**：上表用数据表口径 15,869 / 9,311 / 8,160（人-鼠 / 人-鱼 / 鼠-鱼）。但 2026-10-31 容器复现日志打印的是 `hm=17,611 fh=10,398 fmm=9,058`。两版差异原因未核清（可能是映射版本或过滤阈值不同）。**引用时务必注明用的是哪一版。**
>
> ⚠️ **待确认（coarse 类数）**：素材只写"粗分 9–10 类"，未逐物种列出确切类数。

## 1.5 这章记住三句话

1. 我们要做的事：把三个物种的细胞数据翻译到同一套标准坐标上。
2. 任务形式：用 A 物种已知的细胞类型标签，去猜 B 物种每个细胞是什么类型，**猜得准不准就是方法的好坏**。
3. 三个坑：同源基因只有一部分能对上、细胞类型名字不统一、数据规模差一到两个数量级。

# 第 2 章 三个方法各是什么

> **这章讲什么**：oPCA / scVI / SATURN 三个方法，分别是"怎么翻译菜谱"的三种做法。
> **为什么重要**：整份选型指南的全部依据，就是这三条路各自的强弱差异。搞清楚它们**各自怕什么**，你才知道什么时候该用谁。

## 2.1 先用不含术语的话说一遍

**oPCA（同源基因主成分分析）**
> 把两边能对上的基因挑出来，直接做一次压缩，然后比相似度。
> 相当于：**只翻译双方共有的词汇，然后逐句对照**。

**scVI（单细胞变分推断）**
> 把两个物种的细胞丢进同一个模型里一起训练，让模型自己学出一套低维坐标，同类型的细胞在坐标里自动靠近。
> 相当于：**请一个翻译，让他把全部菜谱读完，自己总结出一份标准版**。

**SATURN**
> 先把每个基因翻译成"蛋白质的语言"，再把一堆基因压成若干个"超级基因"，用超级基因来比。
> 相当于：**不逐句翻译，而是先提取每道菜的"风味特征"，再比风味像不像**。

为什么 SATURN 要走这条绕路？因为它想绕开 1.3 的第一个坑——基因名字对不上。**蛋白序列比基因名更保守**：两个物种的基因即使名字不同、序列有差异，它们编码的蛋白质功能往往还很像。所以"比蛋白"比"比基因名"更抗跨物种。

## 2.2 加上术语，精确说一遍

| 方法 | 一句话定位（术语版） |
|---|---|
| **ortholog-PCA（oPCA）** | 取两物种的 1:1 直系同源基因交集，各自标准化后在共同基因轴上做 **PCA**（主成分分析，找方差最大的几个方向当新坐标），降到 50 维，再用 **KNN**（k 近邻，看最近的 k 个已知标签细胞投票）做标签迁移。 |
| **scVI** | 一个 **VAE**（变分自编码器，一类"压缩再还原"的神经网络），把基因计数建模为负二项分布，把两物种细胞放在一起训练，输出 **10 维** batch-corrected **潜空间**（latent space，模型自己学出来的低维坐标，不是原始基因）。 |
| **SATURN** | 用 **ESM2**（一个蛋白语言模型，输入氨基酸序列输出向量）为每个基因生成蛋白嵌入，再通过**宏基因**（macrogene，把上千个基因加权压缩成几百个"超级维度"）压缩表示，使不同物种的基因即便序列不同也能按蛋白功能对齐。本项目压缩到 **1,000 维**。 |

## 2.3 三方法强弱总表

这是本片最重要的一张表。**"强 / 弱"两列不是主观评价，每一项都有数字或实测撑腰。**

| 方法 | 一句话定位 | 强在哪 | 弱在哪 | 我们为什么选它 |
|---|---|---|---|---|
| **oPCA** | 不做训练、只做一次压缩的**快速基线** | 无需训练、无需 GPU；实测 **约 27 秒**（本机 6 方向全量，26.7 秒 / 峰值 1.31 GB）；完全确定性（同输入必同输出）；文档与 Agent 友好度 **26/30**，可无人值守 | 依赖 1:1 同源对，对应关系弱时信息损失大；**远缘场景全面落后**——人→斑马鱼仅 **0.1506**；批次混合指标也是三者最弱之一 | 它是**下界基线**。任何复杂方法必须先证明自己赢得过它，否则就不值得用 |
| **scVI** | 联合训练出潜空间的**深度生成模型** | 两物种细胞一起训练，远缘场景反超；**CPU 8.5 分钟**（2 核，4,606 细胞 × 9,018 基因 × 50 epoch，峰值 2.37 GB；平台 2c8g 含 IO 实测 15m16s）；潜空间可复用做聚类 / 可视化 | 需要训练、需要调 epoch；首次安装有依赖版本冲突，需要人介入一次；SATURN / SAMap / scVI 各只训练一次，**seed 波动未测**；批次混合三项相对最好但绝对水平仍低 | 它证明了"**深度学习必须 GPU**"这个假设在 1,500 细胞/物种规模上**不成立**——这是本项目最反直觉的结论 |
| **SATURN** | 靠蛋白语义对齐的**跨物种专用**方法 | 专用设计正面绕开"基因名对不上"；宏基因压缩后表示稳健；**但原报告的鼠↔鱼「大幅领先」是评测 bug 造成的**，修正后为 0.4076 / 0.2961，不再领先任何方向 | 需要 **GPU**（原训练在 3080Ti）；部署最麻烦（镜像、蛋白嵌入 `.pt` 全要自己准备）；文档/Agent 友好度仅 **14/30**；`n_q` 只有 459–1309，分母小方差大；批次指标已核实为"**不可补**"（原训练命令丢失，重训会破坏可比性） | 它是"**专用路线**"的代表。选它进来就是要检验：为跨物种专门设计，到底比通用方法强多少 |

### 两个必须跟着看的口径警告

**警告一：SATURN 在鼠↔鱼方向的"领先"在公平口径下翻转了。**

2026-11-08 复核发现：旧算法的 macro-F1 偏高，根因是**评测把真值按源物种词表、预测按目标物种词表查表**（方向颠倒），造成两侧各丢一批细胞。四种约定重算，只有错的那种能复现全部旧值（6/6，accuracy 亦 6/6）。修正后 SATURN 六向为 **0.3522 / 0.2566 / 0.1269 / 0.1640 / 0.3658 / 0.3563**，**一个方向都不赢**；分母同时与其他方法拉齐到 1499–1528。详见 `docs/reports/report-09-corrections-20261108.md`。

所以本项目的结论已改为：**鱼的四方向全部 scVI 领先**。旧版（v6 选型指南）里"鼠↔鱼 SATURN 首选"、以及旧回应稿里「公平口径 0.4560 / 0.4588」的说法**均已作废**——看到旧文档请以 `场景化选型指南-v7-20261108.md` 与 `docs/execution/20261108-更正索引.md` 为准。

**警告二：四个方法的分母不同，分数不能直接比大小。**

| 方法 | 可评估细胞占比 |
|---|---|
| oPCA | 97–100% |
| scVI | 97–100% |
| SATURN | **97–100%**（2026-11-08 更正后；旧文档写的 29–87% 是查表 bug 造成的） |
| SAMap | 0–91% |

分母小的方差更大。真正的比较必须落在**同一批细胞**上（配对检验），不能只看两个百分数谁高。

## 2.4 三者不是"谁替代谁"，是"在什么场景下选谁"

**这句话请记死：这三个不是"谁替代谁"的关系，是"在什么场景下选谁"的关系。**

不存在"SATURN 出来后 oPCA 就废了"这回事。原因很实在：

- oPCA 慢在能力、快在速度——27 秒跑完，别人还在装环境；
- scVI 强在远缘、弱在要调参——装一次环境就能用，但版本冲突第一次会咬你；
- SATURN 强在专用、弱在门槛——强到能赢，也可能因为缺一个 `.pt` 文件而完全跑不动。

按场景选：

| 你的处境 | 选谁 | 依据（数字） |
|---|---|---|
| 只有 CPU，想先把流程跑通 | **oPCA** | 约 27 秒，无需训练 |
| 人 ↔ 小鼠（近缘） | **oPCA 或 scVI**，基本打平 | 两向均值 0.6582 vs 0.6289；配对检验一侧不显著、一侧 oPCA 显著更高 |
| 人 ↔ 斑马鱼（远缘） | **scVI** | 0.4014 vs oPCA 0.1506 |
| 鼠 ↔ 斑马鱼（远缘） | **scVI** | SATURN 修正后 0.4076 / 0.2961（v2 映射），四向仍全部落后 scVI |
| 跨门（七鳃鳗 ↔ 小鼠） | **都不行** | 两法准确率 4.6–5.8%，随机猜约 7.7%，多数类基线 21.7% / 30.6% |

**最后一行是这份手册里最重要的诚实**：跨门不是"数据不够"或"没调好"，而是当前这套「共同基因轴 + 单层细胞类型注释 + KNN 标签迁移」的范式在这个尺度上不成立。把这个负结果写清楚，比含糊地说"未做"有价值得多——**它排除了一条路**。

## 2.5 这章记住三句话

1. **oPCA 是快速基线**（27 秒、免训练），一切复杂方法都得先赢过它。
2. **scVI 是深度生成模型**（8.5 分钟 CPU 就够），远缘场景的主力。
3. **SATURN 是跨物种专用**（蛋白嵌入 + 宏基因），强但要 GPU、门槛最高。

**记住第 4 句**：选型不是排名，是匹配——**先问"我在什么场景"，再问"该用谁"**。
