### 2.7 输入层差异：SAMap 侧用的是 1:1 直系同源，不是原文的 BLAST 全同源图

**源码级确认（2026-11-11 第 58-59 轮）**。读 `scripts/run_samap_compliant_v98.py`（437 行，
我们标注为「合规」的版本）：

```python
# :277
def build_gnnm_from_orthologs():        # 手工从 MGI/ZFIN 直系同源建图
    ...
    return gnnm

# :349-350
gnnm = build_gnnm_from_orthologs()
sm = SAMAP(sams, keys={s: TRUTH_COLUMN for s in sams}, gnnm=gnnm)   # 传自建图
```

**v71（legacy `local_samap3.py`）与 v98（`run_samap_compliant_v98.py`）都是这样做的。**

→ **我们在 SAMap 这一侧，从未使用 BLAST 全同源图。**

| 维度 | 原文（SAMap 官方流程） | 我们 |
|---|---|---|
| 同源图来源 | **BLAST** 全蛋白组互搜 | MGI + ZFIN **直系同源** |
| 图的语义 | 一对多、序列相似性加权 | **1:1 二值**（有/无） |
| 覆盖 | 全基因 | 仅有直系同源记录的基因 |

**为什么原文那份跑不了（源码级）**：

```python
# samap/mapping.py:1052-1074
def _calculate_blast_graph(ids, f_maps="maps/", eval_thr=1e-6, reciprocate=False):
    if os.path.exists(f_maps + f"{id1}{id2}"):
        fA = f_maps + f"{id1}{id2}/{id1}_to_{id2}.txt"       # 只读预生成的表
    else:
        raise FileExistsError("BLAST mapping tables ... not found")
```

→ `SAMAP` 类**不跑 BLAST，只读预生成的 `maps/*.txt`**。
→ PyPI 的 `samap` 包（wheel 与 sdist 都是）**只含 4 个模块，不含任何 BLAST 脚本**
（`SOURCES.txt` 确认；全仓库搜 `blastp`/`makeblastdb`/`blastn` **0 处命中**）。
→ BLAST 步骤在 **SAMap 的 GitHub 仓库**里，不在分发包里。

**⚠️ 现行结论**：这条差异**已查明、可写**；但「用 BLAST 重跑一遍」**尚未做**，
且不是「改一行」——需要 BLAST+、三物种蛋白组、官方脚本、以及 `maps/*.txt` 的正确格式
（格式错了会静默误解析）。

**→ 这是目标③「输入」维度（`SAMap 1:1 vs Compara vs BLAST`）的第一个已知成员。**

#### 覆盖率量化：1:1 图覆盖不到一半基因

| 物种 | 基因总数 | 有同源记录 | 无同源记录 | **覆盖率** |
|---|---|---|---|---|
| human | 32732 | 17898 | 14834 | **0.5468** |
| mouse | 32379 | 11613 | 20766 | **0.3587** |
| zebrafish | 27661 | 15419 | 12242 | **0.5574** |

> ⚠️ **限制**：该表的解析是**启发式**的（按列位取符号、未做大小写/别名归一），
> **不是管线里的真实匹配**。参照 v71 记录「human 32,732 → 19,302 匹配」（≈59%），
> 本表 human 为 54.68%——**同量级但不等**，差异来自匹配细节。
> **→ 应表述为「量级参考」，不是精确覆盖率。**

**但结论是稳的**：

> **我们的 1:1 同源图覆盖不到一半基因**（human ≈55%、**mouse ≈36%**、zebrafish ≈56%），
> **近半基因在图上没有任何连接**。原文的 BLAST 全同源图会把其中一部分连上。
> **→ 输入层差异的量级不是「略有不同」，是「近一半基因缺席」。**

### 2.8 拟合方式：我们的 oPCA 是 transductive 的（PCA 看到了目标细胞）

**源码证据**（`scripts/ortholog_pca_dcs_v3_fixkey.py:278-282`）：

```python
X_joint = np.vstack([Xs, Xt]).astype(np.float64)      # 源 + 目标一起堆
Z = PCA(n_components=NPCS, random_state=SEED).fit_transform(X_joint)
```

→ **PCA 在「源物种 + 目标物种」细胞上联合拟合，拟合时已看到目标细胞**
→ **oPCA 是 transductive 的，不是 inductive。**

**为什么重要**：真实部署时**拿不到目标物种细胞**；transductive 拟合泄漏目标分布信息，
并让我们的数与 inductive 方法**不可直接比**。

**实测（把 `PCA(...).fit_transform(X_joint)` 改成 `PCA(...).fit(Xs)` + `transform(X_joint)`）：**

| 方向 | transductive acc | **inductive acc** | Δ |
|---|---|---|---|
| 人→鼠 | 0.8618 | **0.8186** | **-0.0432** |
| 鼠→人 | 0.7369 | **0.5144** | **-0.2225** |
| 人→斑马鱼 | 0.1811 | **0.2056** | **+0.0245** |
| 斑马鱼→人 | 0.2788 | **0.0949** | **-0.1839** |
| 鼠→斑马鱼 | 0.273 | **0.2566** | **-0.0164** |
| 斑马鱼→鼠 | 0.5967 | **0.6625** | **+0.0658** |

- Δ 范围 **-0.2225 ~ 0.0658**，均值 -0.0626
- **不是单调**：两向显著下降（鼠→人 −0.2225、斑马鱼→人 −0.1839），
  两向反而上升（人→斑马鱼 +0.0245、斑马鱼→鼠 +0.0658）
- 两条大跌的都是 **「→human」** 方向

**⚠️ 连带影响**：所有基于 transductive oPCA 的配对结论都可能改变，
「近缘/远缘」推荐表需在 inductive 口径下复核。

### 2.9 配对复核：拟合方式一换，近缘结论又变了（四种设置四个答案）

把 oPCA 换成 inductive 变体、其余不变，个体级配对重做，**3 条翻转**：

| 方向 | 比较 | transductive Δ | 显著 | **inductive Δ** | **显著** |
|---|---|---|---|---|---|
| 人→鼠 | oPCA vs scVI | -0.0247 | ns | **-0.1498** | **SIG** |
| 鼠→人 | oPCA vs scVI | +0.0833 | ns | **-0.1531** | **SIG** |
| 人→斑马鱼 | oPCA vs saturn | +0.0224 | ns | **-0.0370** | **SIG** |

#### 近缘（人↔鼠）：同一比较，四种设置四个答案

| 设置 | 人→鼠 | 鼠→人 | 表面结论 |
|---|---|---|---|
| KNN + 逐细胞 + transductive | ns | **oPCA 胜** | 一向平一向胜 |
| KNN + 按个体 + transductive | ns | ns | 打平 |
| **LR** + 按个体 + transductive | **oPCA 胜** | **scVI 胜** | 各赢一向 |
| **KNN + 按个体 + inductive** | **scVI 胜** | **scVI 胜** | **scVI 两向全胜** |

**→ 而远缘（鱼四向）在四种设置下都是 scVI 胜（全部 SIG 且为负）。**

**这是本文最硬的一条结论**：

> **「近缘哪个方法更好」在不对齐「重抽样单位 + 评估器 + 拟合方式」之前，没有唯一答案；**
> **而「远缘 scVI 更优」在四种设置下都稳健。**

**→ 直接回答了「什么结论值得写」：远缘可以写，近缘不能。**
