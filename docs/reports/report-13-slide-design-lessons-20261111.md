## 一、学习来源（不是凭感觉）

| 来源 | 性质 | 用它做了什么 |
|---|---|---|
| `visual-taste` 技能（本机） | 可执行规范 | 层级/比例/色彩/字体/质检流程；「反 AI 味清单」 |
| 技能附件 `typography-cn.md` | 中文排版硬指标 | 字号梯度、行距、行宽、标点规则 |
| 技能脚本 `check_contrast.py` | 可运行体检 | 配色对比度量化，找出 2 处不合格 |
| 组员版 `课题5_第三次汇报.pptx` | **实测基准** | 量出它的边距、栅格、配色族、字号分布 |
| 自己渲染的 v1–v3 版 | 反例 | 逐条对照缺陷 |

> 关键认识：**做一个好 PPT 的前提是先有可量化的基准**，不是「多试几版看哪个顺眼」。

## 二、量出来的基准（组员版实测，可复现）

| 维度 | 组员版实测 | 我的 v3 | 差距 |
|---|---|---|---|
| 内容左边距 | **1.01″** | 0.67″ | 贴边太紧，显得挤 |
| 卡片宽 / 间距 | 2.52″ / **0.41″** | 2.86″ / 0.13″ | 间距只有它的 1/3，卡片糊成一片 |
| 背景色层次 | **4 档浅底** `#EFF6FA` `#E3EAF0` `#F5F8FB` `#FFFFFF` | 只有白 | 没有分区，靠线条硬分 |
| 强调色系 | **4 族** 蓝 `#0876B2` / 青 `#168D9D` / 金 `#C88F18` / 砖红 `#B45C54` | 深蓝 + 金（2 族） | 表达力只有它一半 |
| 文字灰阶 | **3 档** `#153957` / `#5E7182` / `#82929F` | 黑 + 一个灰 | 层级做不出来 |
| 主视觉形态 | 流程图、等式行、**原生条形图** | 文本框 + 矩形 | 它是「一页一个视觉模型」，我是「一页一堆字」 |

**致死结论**：组员版的字号跟我一样（标题 24pt、正文 11pt），**它不是靠字大取胜，是靠"图形化表达"取胜**。我先前把问题归因为「字太小」，方向错了。

## 三、我犯的七个缺陷（对照 `visual-taste` 清单）

| # | 缺陷 | 命中规则 | 改法 |
|---|---|---|---|
| 1 | 卡片左侧一条竖色条 | 「AI 味第一名」 | 竖条改为**顶部横条**（有信息量：区分方法族） |
| 2 | 页眉下通栏色条 / 标题下强调线 | 「AI 味第一名」 | 模板自带的顶栏保留（学校要求），自己不加装饰线 |
| 3 | 每页都是「标题 + 要点」同一版式 | 「每页同一个版式」 | 收敛为四种内容区：图表 / 卡片 / 流程 / 数字 |
| 4 | 用文本框和矩形模拟表格 | 无信息量的装饰 | 主结果、跨门、修正对比全部改用**原生条形图** |
| 5 | 标题是「一、二、三」编号 | 标题不写结论 | 改成观点句：「谁赢了：一张表就够」 |
| 6 | 强调色只用来装饰 | 「强调色只做一件事」 | 金色只标「每行最高值」，其余一律不用 |
| 7 | 讲造价（¥2.47） | 与结论无关 | 整页删除，交付物里留证据即可 |

## 六、还学到的两条程序性教训

1. **不要看旧渲染图下判断**。我一度以为段标位置错了，实际是重建 PPT 后**没有重新转 PDF**，读到的是上一版的图。教训：`改 pptx → 转 pdf → 渲染 png → 看图` 必须是一条连续链。
2. **坐标级指令对人是无效的**。人手做 PPT 没有坐标输入框，后续交接只给「区块关系 + 数据 + 一句话结论」，不给英寸。
