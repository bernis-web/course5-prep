## 第 4 页 · 从原始细胞到表格单元格：八个环节

八个环节：

| # | 环节 | 落盘物 |
|---|---|---|
| 1 | 原始 h5ad | 三物种心脏单细胞 |
| 2 | 归一化 | normalize_total(1e4) + log1p |
| 3 | 表示层 | 同源交集 + PCA-50 |
| 4 | 角色划分 | src = reference，tgt = query |
| 5 | KNN15 | cosine，倒距离加权 |
| 6 | 逐细胞预测 | 含 confidence 与排除原因 |
| 7 | 排除与计数 | correct / eligible = n_q |
| 8 | metrics.json | SHA-256 锚定 |

核心句：换掉任何一环的定义，最终百分比就会变——所以复核必须沿这条链走，而不是从表里抄数。

补充：每一环都有落盘物，第三方可以据此重算任意一个单元格。

## 第 5 页 · 实例拆解：86.18% = 1,297 ÷ 1,505

| 环节 | 内容 | 取值 |
|---|---|---|
| 输入 | reference = 人 ｜ query = 鼠 | 1,528 / 1,535 |
| 同源基因 | 人鼠 1:1 直系同源交集 | 15,869 |
| 表示层 | 人+鼠联合 PCA-50（seed 0） | 3,063 × 50 |
| 评分 | KNN15，cosine，倒距离加权 | k = 15 |
| 排除 | 鼠侧 status ≠ active | 剔 30 |
| eligible query | 1,535 − 30 | n_q = 1,505 |
| 正确数 | 逐细胞预测 == 真值 | 1,297 |

**核心句**：86.18% = 正确预测数 ÷ 排除后仍有资格的 query 细胞。不是从表里抄出来的。

逐类分解（confusion 摘录）：内皮 720/725、成纤维 255/360、免疫 197/202、心肌 19/47；
错误集中在成纤维→平滑肌（82）与心肌→内皮（27）。

主源：`results/pilot-v1/ortholog-pca-v98/metrics.json`，SHA `b2b3ac6b…c725`，本地已独立复算。

## 第 6 页 · 分母会变，所以必须一起报

- 同一个 coarse 层，query 细胞 1,535 个，排除 30 个后不再进入分母。
- eligible 1,505，coverage 98.05%。

| 必须并列报的量 | 定义 | 为什么必须报 |
|---|---|---|
| accuracy | correct ÷ n_q | 主指标 |
| n_q / coverage | 进入分母的细胞数 | 排除规则一改，分母就变 |
| majority | 最大真值类占比 | 无信息基线：准确率 0.4817，macro-F1 仅 0.0813 |
| shuffle_p | 预测向量置换检验 | 只回答"是否优于随机"，不是多数类检验 |

**核心句**：只报 accuracy，等于把分母的变化藏起来。

## 第 7 页 · 同一份预测，两个 macro-F1

- **truth-only**（平台 scVI 脚本默认）：**0.4516** —— 只按真实标签集取平均；预测多出来的类被忽略。
- **union**（本项目跨方法统一口径）：**0.4014** —— 真实 ∪ 预测 一起取平均；预测多出来的类记 F1 = 0。

差值来源：被预测出来、但真值里根本不存在的类。这类越多，两个口径差得越大。

**核心句**：单独看 truth-only 没问题，但它不能和别的方法并列；跨方法对比一律用 union，从 18 个逐细胞预测文件独立重算。

例子：人→斑马鱼 coarse，两个口径差 0.05——足以改变"是否高于基线"的判断。

## 需要提前准备的两个追问

1. **"为什么不直接用 macro-F1 报就好了？"**
   答：macro-F1 对少数类敏感，但它依赖标签集合的定义；同一份预测在 truth-only 与 union 下差 0.05。
   所以指标之外必须同时交代口径与分母。

2. **"这些数字能复现吗？"**
   答：能。主源是 metrics.json + 逐细胞预测文件，脚本与输入的 SHA-256 都记在 manifest 里；
   本地已用独立实现重算过 accuracy（18/18 一致）与 macro-F1（差异全部可由口径解释）。
