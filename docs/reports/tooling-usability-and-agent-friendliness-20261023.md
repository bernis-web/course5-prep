# 四方法文档质量与 Agent 友好度评分（2026-10-23）

> 课程要求项之一。评分依据**本项目实际运行经验**，不是 desk research 的主观印象。
> 每个分数后面都给出本项目里对应的具体事件，方便复核。
> 评分尺度：1 = 严重阻碍（需数小时到数天排障），3 = 可用但有明显摩擦，5 = 一次成功、无需读源码。

---

## 一、评分维度

| 维度 | 含义 | 对 Agent 的意义 |
|---|---|---|
| A 安装与依赖 | 从零到可 import/可执行需要多少步、多少坑 | 决定能否在无人值守容器里跑起来 |
| B 文档完整性 | 官方文档是否覆盖安装、输入格式、关键参数 | 决定 agent 要不要读源码猜 |
| C 调用接口 | CLI / Python API 是否稳定、参数是否自解释 | 决定能否脚本化 |
| D 输出可解析性 | 产物是否结构化（JSON/TSV），还是只能人眼看 | 决定能否自动核对 |
| E 错误可诊断性 | 报错是否指向根因 | 决定 agent 能否自愈 |
| F 复现确定性 | 单 seed 是否可复现、是否有隐藏随机性 | 决定结论能否被第三方重算 |

## 三、逐项依据（本项目实证）

### 3.1 ortholog-PCA（自建基线）

| 维度 | 分 | 依据 |
|---|---|---|
| A 安装 | 5 | 只需 numpy / scipy / anndata / scanpy / sklearn，无 GPU、无编译 |
| B 文档 | 3 | 自建脚本，有模块级 docstring 与 HARDSTOP 码说明，但没有外部文档站 |
| C 接口 | 4 | 单一 `python3 script.py`，参数走环境变量（`OPCA_OUT_ROOT` 等），可脚本化 |
| D 输出 | 5 | `metrics.json` + `predictions/*.json` + `manifest.json` + `sha256.tsv`，全结构化 |
| E 错误 | 4 | 自定义 `HARDSTOP\|...` 前缀 + 退出码（2 预检 / 3 输出越界 / 4 基因轴过小） |
| F 复现 | 5 | 单 seed，纯确定性 SVD；本地 30 秒复跑一致 |

**Agent 结论**：最容易自动化，但"文档在代码里"，agent 必须先读 docstring。

### 3.2 scVI

| 维度 | 分 | 依据 |
|---|---|---|
| A 安装 | 3 | `pip install scvi-tools` 一条命令，但**版本地狱真实存在**：本轮 `pylibs_full` 里的旧 anndata 抢在镜像 0.10.8 前面，导致 `mudata` 找不到 `AlignedViewMixin`，`import scvi` 直接失败 |
| B 文档 | 5 | scverse 生态文档最完整，`setup_anndata` / `train` / `get_latent_representation` 都有示例 |
| C 接口 | 5 | Python API 语义清晰；`SCVI(adata, n_latent=10)` + `train(max_epochs=50)` 即可 |
| D 输出 | 5 | `model.get_latent_representation()` 直接返回 ndarray；`history` 可查 loss |
| E 错误 | 4 | 本次报错直接指出 `AlignedViewMixin` 与 anndata 路径，定位快；但版本冲突类错误仍需要经验 |
| F 复现 | 4 | `scvi.settings.seed` 可设；但 torch 多线程/浮点非确定性可能带来微小差异 |

**Agent 结论**：接口与文档最好，**唯一门槛是依赖版本**。踩过一次之后可复用同一套修复。

### 3.3 SATURN v99

| 维度 | 分 | 依据 |
|---|---|---|
| A 安装 | 2 | 需要 GPU 镜像（本项目用 `SATURN--22`）；CPU 上训练不可接受 |
| B 文档 | 3 | 官方 repo 有 README，但 macrogenes / ESM2 嵌入的准备步骤描述不完整 |
| C 接口 | 3 | 有 CLI，但要先准备蛋白嵌入与 macrogene 映射，参数链路长 |
| D 输出 | 2 | 原生输出是嵌入，标签迁移与评分要自己另写 |
| E 错误 | 2 | 报错多指向内部张量形状，难以直接从消息定位到输入问题 |
| F 复现 | 2 | 依赖 GPU 与镜像版本；本项目只在单镜像上验证过 |

**Agent 结论**：能跑，但每一步都要人盯着；不适合完全无人值守。

### 3.4 SAMap v98

| 维度 | 分 | 依据 |
|---|---|---|
| A 安装 | 2 | 依赖 samap / samalg / hnswlib，需预建 pylibs 栈（210 MB tar） |
| B 文档 | 3 | 有示例 notebook，但键名约定（`"ms"` vs `"mouse"`）未文档化 |
| C 接口 | 2 | 脚本需 `sed` 改键名才能跑（本项目 `s/"ms": "mouse"/` 修复） |
| D 输出 | 2 | 输出是同源图与嵌入，标签迁移需另写评分器 |
| E 错误 | 1 | **本项目排障 14 次迭代才跑通**（见 `docs/checkpoint-flash-20261002-evening.md`） |
| F 复现 | 1 | 依赖随机图构建与 hnswlib 近似检索，复现稳定性最差 |

**Agent 结论**：四个方法里 Agent 友好度最低。能跑通是靠大量人工试错，不是靠文档。

## 四、对"Agent 能否独立完成一次跨物种分析"的判断

| 方法 | 无人值守可行性 | 需要人介入的环节 |
|---|---|---|
| ortholog-PCA | ✅ 可以 | 只需确认输入路径 |
| scVI | ⚠️ 首次需要人 | 依赖版本冲突的识别与修复；修复后可以 |
| SATURN | ❌ 不建议 | 镜像选择、GPU 资源、嵌入准备 |
| SAMap | ❌ 不建议 | 键名约定、依赖栈、随机性 |

**一句话**：如果目标是"让 agent 独立跑一次跨物种整合"，从 oPCA 或 scVI 起步；
SATURN 与 SAMap 目前仍属于"需要专家在旁边"的工具。

---

## 五、评分本身的局限

1. **样本单一**：每个方法只在本项目这一套数据（1,500 细胞/物种）上跑过，
   换规模、换物种、换镜像，分数可能变。
2. **"文档"分含主观判断**：B 维度没有客观量表，依据是"是否需要读源码才能用"。
3. **SATURN / SAMap 的低分部分来自本项目环境**（DCS 镜像、离线无网络），
   不代表在标准云环境下的表现。
4. 本评分**不构成对工具质量的评价**——它衡量的是"自动化友好度"，不是科学价值。

## 六、可改进项（若要把分数提上去）

| 全部 | 统一 `metrics.json` schema | D 全面 +1 |
