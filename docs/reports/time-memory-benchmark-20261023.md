# 四方法时间与内存实测汇总（2026-10-23）

> 课程要求项之一。**说明：以下全部是单次任务记录，不是受控 benchmark。**
> 数据来源：DCS 任务详情页的 CPU / 内存 / IO 字段，以及本地运行日志。逐条可回溯到任务号。

---

## 二、能得出的结论

1. **oPCA 是唯一"秒级"的方法**：本地 30 秒，DCS 上 14 分半（含数据加载与 IO）。
2. **scVI 在门内规模下 CPU 完全够用**：8.5 分钟实际计算、2.37 GB —— 推翻了"深度学习必须 GPU"的假设。
3. **scVI 的开销随细胞数近似线性放大**：4,606 细胞 8.5 分钟 → 55,694 细胞约 3.5 小时（12 倍细胞、约 24 倍时长，含 IO 与 KNN）。
4. **SAMap 比 oPCA 慢 30 倍以上**（16m24s vs 30s），且需要预建依赖栈。
5. **SATURN 没有可用数据**：GPU 任务，当时没有记录 CPU/内存字段。

---

## 三、为什么这不是受控 benchmark

| 问题 | 说明 |
|---|---|
| 排队时间混入 | 墙钟时长包含排队（oPCA 那次占了 21 分钟），只有"实际计算"才有意义 |
| 资源档不同 | SAMap 是 1c4g，其余是 2c8g，不能直接比时长 |
| 单次记录 | 没有重复测量，无法给置信区间 |
| 输入不同 | 门内与跨门的细胞数差 12 倍，不能横向比较 |
| SATURN 缺数据 | GPU 任务的 CPU/内存字段平台未记录 |

**结论**：这张表适合回答"大概要多久、大概要多少内存"，不适合做精确的性能排名。

---

## 四、如果要变成受控 benchmark（未做）

最小可行方案：

1. 固定输入（同一份 4,606 细胞数据）；
2. 固定资源档（全部 2c8g，SATURN 用同规格 GPU）；
3. 每个方法重复 3 次，报中位数与范围；
4. 只统计"实际计算"时间（从容器启动到脚本结束），排除排队；
5. 内存取 cgroup 的 `memory.peak`。

成本估计：oPCA/scVI/SAMap 各 3 次约 ¥1–2；SATURN 若需 GPU 另计。
**本轮未做**，原因是边际价值低于其余缺口。

## 五、对选型的实际意义

| 场景 | 时间约束 | 结论 |
|---|---|---|
| 只有 CPU、要快 | 分钟级 | 选 oPCA（30 秒） |
| 只有 CPU、能等 | 十分钟级 | 选 scVI（8.5 分钟），效果更好 |
| 有 GPU、鼠↔鱼 | 小时级 | 选 scVI（0.4248 / 0.4786）；SATURN 修正后 0.4076 / 0.2961，不再最高 |
| 5 万细胞以上 | — | scVI 要 3.5 小时、¥2.06，需先评估预算 |
