# 复现有效性 memo（给老师）

**日期**：2026-11-11　|　**课题**：跨物种单细胞整合基准测试（XenoTransfer）
**结论一句话**：**我们的分数低，第一原因不是方法本身，而是我们没有按原文配置跑；在查清这一点之前，「哪个方法更好」的结论都不能写。**

---

## 一、您问的问题与我们的回答

您问：**"按照 SATURN 自己的文章，结果应该是很好的；你们这个数是偏低还是偏高？"**

我们的回答分三层：

**第一层：我们已经发现，我们跑的不是原文的 SATURN。**
对照官方代码（`saturn-src/train-saturn.py`）与官方 `--help` 实测默认值，我们此前的配置被砍过：

| 参数 | 我们此前（v71） | 官方默认 | 差距 |
|---|---|---|---|
| `hv_genes`（高变基因数） | **2,000** | **8,000** | 1/4 |
| `num_macrogenes`（宏基因数） | **1,000** | **2,000** | 1/2 |
| `hv_span` | **1.0** | **0.3** | 为绕一个 loess bug 改的 |
| 基因宇宙 | 每物种 HVG top-**2,500** | 全基因 | — |
| 评估器 | KNN-15 | **logistic regression** | — |
| 设备 | CPU 1c4g | GPU | — |

**所以这不是"方法比较"，是"配置比较"。** 您说的"SATURN 文章里应该很好"，前提是**按它的配置跑**。

**第二层：原文的数据规模我们也差得不多，但不是主因。**
全量数据就在平台上（人 30,000 / 鼠 60,471 / 斑马鱼 50,000 细胞），我们只用了 1,528 / 1,535 / 1,543。
差距是 **20–40 倍**（不是我们原先以为的 100–1000 倍）。
但注意：**oPCA 和 scVI 在 1,500 细胞上已经跑到 0.86 / 0.92（人→鼠）**——
说明 1,500 细胞足够学到信号，**规模很可能不是低分主因**。

**第三层：我们已经在按原文配置重跑。**
官方配置（hv_genes 8000 + macrogenes 2000 + hv_span 0.3 + pretrain 200 epochs）的训练任务
已经在平台上提交并排队。**这一组数字出来之前，我们不会写任何"SATURN 行不行"的结论。**

---

## 二、除了配置，我们还查出四处会影响结论的问题

**这四处都是我们自己发现的，而且都已量化：**

**① 评测口径未对齐（直接影响和原文比）**
我们用的是 **union macro-F1**（预测里多出的类记为 F1=0），而原文多为 truth-only 类口径。
实测：union − truth-only 在六个方向上差 **0 ~ −0.0523**（全部 ≤0）。
→ **拿我们的数直接和原文比，会显得偏低。** 比较前必须统一口径。

**② 标签空间粒度未对齐**
同一批预测，在 exact / fine / coarse 三层上的 accuracy **六个方向全部单调递增**（越粗越高）。
例：鼠→人 0.4084（exact）→ 0.7369（coarse），差 **0.33**。
→ 不说明粒度，跨论文比较**没有意义**。

**③ 置信区间算窄了（方法学问题）**
我们此前用**逐细胞**重抽样算 CI。但同一供体/同一颗心脏里的细胞不独立，
正确做法是**按个体整群重抽样**。实测个体级 SE 是细胞级的 **1.47–3.88 倍**。
→ 修正后，**两条原本"显著"的结论变成了不显著**（见下）。

**④ 我们曾把 macro-F1 当成 accuracy 填进表里**
已自查并更正。SATURN 的真实 accuracy 是 0.5887 / 0.2271 / 0.1811 / 0.2147 / 0.3036 / 0.4565
（此前误填的 0.3522 / 0.2566 / … 是 macro-F1）。

## 三、修正后的三条主结论（现状）

| 场景 | 结论 | 依据 |
|---|---|---|
| **近缘（人↔鼠）** | ⚠️ **结论不稳健——依赖「重抽样单位 + 评估器 + 拟合方式」三者的选择**，见下方四行表 | 同一条比较在**四种设置下四个答案** |
| **远缘（鱼四向）** | **统一选 scVI**，四种设置下全部显著 | Δ = −0.2454 / −0.2159 / −0.1342 / −0.0600（KNN），LR 与 inductive 下同向 |
| **跨门（七鳃鳗↔鼠）** | 目前**不能说"方法不行"** | 暂无正对照；且标签空间排掉了 62.2% 小鼠细胞 |

### ⚠️ 近缘结论为什么不能给（这是本次最要紧的一条）

同一条比较（oPCA vs scVI，人↔鼠），只换**重抽样单位**、**评估器**或**拟合方式**，答案就变：

| 设置 | 人→鼠 | 鼠→人 | 表面结论 |
|---|---|---|---|
| KNN-15 + 逐细胞 + transductive | 不显著 | **oPCA 显著胜** | 一向平、一向胜 |
| KNN-15 + **按个体** + transductive | 不显著 | 不显著 | **打平** |
| **logistic regression（官方）+ 按个体** | **oPCA 显著胜（+0.1426）** | **scVI 显著胜（−0.0783）** | **各赢一向** |
| **KNN + 按个体 + inductive（修正后）** | **scVI 显著胜（−0.1498）** | **scVI 显著胜（−0.1531）** | **scVI 两向全胜** |

**→「哪个方法在近缘更好」，在不对齐「重抽样单位 + 评估器 + 拟合方式」之前，没有唯一答案。**

我们**不会再给近缘的方法推荐**；只会写"需在指定评估器与拟合方式下报告"。

**对比之下，远缘（鱼四向）在四种设置下都是 scVI 胜**——说明**远缘结论稳健、近缘结论脆弱**。
这个对比本身有价值：它告诉我们**哪些结论值得写进论文，哪些只能当限定条件下的观察**。

### 补充：我们还发现自己的实现有三处口径偏离（都已量化）

1. **重抽样单位**：此前用逐细胞，个体级 SE 是细胞级的 **1.47–3.88 倍**（CI 过窄）；
2. **拟合方式**：oPCA 的 PCA 在「源+目标」上联合拟合（**transductive**），
   改成 inductive 后 **鼠→人 0.7369→0.5144（−0.22）**、斑马鱼→人 0.2788→0.0949（−0.18）；
3. **输入**：SAMap 侧用的是 MGI/ZFIN 的 **1:1 直系同源**，而原文用 **BLAST 全同源图**；
   我们的 1:1 图**覆盖不到一半基因**（human 54.7% / **mouse 35.9%** / zebrafish 55.7%）。

> 附：我们此前三次修正也都在同一方向——
> 第一次把"鼠↔鱼翻转为 scVI 更好"改成"SATURN 从未赢过"；
> 第二次把"近缘一向平一向胜"改成"打平"；
> 第三次把"打平"改成"各赢一向"；
> 这一次（inductive 口径）改成"scVI 两向全胜"。
> **四次修正都让结论变窄，但都更经得起追问。** 这正是本课题真正在研究的现象。

## 五、关于论文（您问的"能不能发"）

**诚实评估：现在这套不能直接发。**

缺的不是"结果不好看"，而是**三样地基**：
1. **正对照**——审稿人第一问就是"你怎么证明实现正确"；
2. **指标与口径一致**（现在是半新半旧）；
3. **完整可复现包**（SATURN 的训练命令此前缺失、SAMap 的运行时脚本与仓库内不一致）。

**但有一条真正值钱的东西**：我们查出的"**评测口径会改变结论**"这个现象。
它不是"我们方法的卖点"，而是**领域内的普遍陷阱**——包括"重抽样单位"、"粒度对齐"、
"union vs truth-only"三类。

**我们建议的主线**：把论文从"哪个方法赢"改成
**"在什么输入与评测条件下，跨物种标签迁移的结论才可信"**。

**可能的去处**（按现实程度排）：
- 方法学/负结果类：PLOS ONE / Scientific Reports / BMC Bioinformatics（~3–4）
- 严格 benchmark + 评测审计：Briefings in Bioinformatics（~6–8，需 3–6 个月补实验）
- 会议短篇先占坑：MLCB workshop / ACM-BCB benchmark track

**不建议**投 Nature Methods / Genome Biology 的方法论文——当前证据量级不够。

## 六、两条纪律（我们给自己定的，也请您监督）

1. **不把 transductive 写成 held-out**；不按总分排冠军，只做"场景 → 方法"；
2. **任何 macro-F1 必须带"union 口径 + 分母 + mapping 版本"三件套**。
   这条是我们踩了坑之后定的——**没有它，数字是对的也会被误读**。
