# ⚠️ 本目录 metrics.json 字段说明书

**本文件由 2026-11-11 溯源审计生成。改数字之前先读这一页。**

## 哪个字段能用

| 字段 | 状态 | 说明 |
|---|---|---|
| `data.n_cells` / `n_genes` / `preprocess` / `knn` / `shuffle_p` | ✅ 可用 | 与混淆矩阵一致 |
| `*.directions.*.acc` | ✅ **可用** | 与混淆矩阵的 micro-F1 **逐位相等**（0.0575 / 0.0516 / 0.0582 / 0.0457） |

| `*.directions.*.macro_f1_union` | ❌ **不可引用** | 见下 |

## `macro_f1_union` 为什么不可引用

存值 0.0711 / 0.0732 / 0.0652 / 0.0802；用同目录混淆矩阵重算是
**0.0235 / 0.0257 / 0.0241 / 0.0267**，差约 3 倍。

2026-11-11 穷举了 16 类变体（8 种标准 macro/micro/weighted + zero_division 开关、
4 种标签错位组合、top-k 子集、支持度阈值子集），**全部复现不出存值**，且四个方向没有任何一种
口径能同时对上。而 `acc` 逐位相等，说明混淆矩阵与存值是同一次运行的产物——
所以这不是「口径差异」，是 `macro_f1_union` 那段计算本身的问题，来历已无法复原。

详见 `docs/reports/audit-crossphylum-provenance-20261111.md`；
复算脚本 `scripts/trace_crossphylum_mf1.py`。

## 引用规则

```
✅ "跨门 macro-F1 = 0.0235 / 0.0257 / 0.0241 / 0.0267（13 类并集、macro、zero_division=0）"
❌ "跨门 macro-F1 = 0.0711 / 0.0732 / 0.0652 / 0.0802"
❌ "离多数类基线差 11–13 倍"（那是拿旧 mf1 比基线，口径不可混）
✅ "同向 macro-F1 比多数类基线低 12%–29%；按 accuracy 是 3.8–6.7 倍"
```

## 为什么留值不删

删了就没法解释「我们怎么发现它不对的」。它现在的作用是**反例**：
让后来的人一眼看到「看起来合理但复算不出来的数」长什么样。
真要改，加新字段（例如 `macro_f1_strict`），不要覆盖旧字段。
